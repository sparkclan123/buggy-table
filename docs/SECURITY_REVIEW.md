# Security review — MySQL and Redis adapters

Reviewed on 2026-10-14. This is a code review and targeted test record, not an independent penetration test or a production certification.

## Isolated OpenVPN addition — 2026-10-20

Each VPN-backed session owns one local Linux container and a fixed database destination. The runtime rejects remote Docker contexts. It does not mount host directories or the Docker socket, use host networking, or change host routes/DNS. Database and private-DNS sockets bind to `tun0` and a dedicated routing table with a terminal unreachable rule. OpenVPN loss closes active forwarded streams; no direct-network retry is implemented. DNS cache lifetime is bounded by the answer TTL and is cleared on tunnel loss. Database TLS continues to authenticate the original hostname.

Imported client configurations have an explicit option/block allowlist; scripts, plugins, external files, management listeners and TAP are rejected. Only the bundled up/down script runs. Container privileges are limited to NET_ADMIN/NET_RAW and `/dev/net/tun`, with a read-only root, private bounded tmpfs, no-new-privileges and CPU/memory/PID limits. These measures are not a guarantee against a malicious Docker daemon or host administrator.

Config/key/password fields are AES-256-GCM encrypted with owner/profile-bound additional authenticated data. The key uses the existing local OS credential provider; it is never returned to the frontend. The encrypted file uses atomic replacement and limits. UI metadata remains plaintext. Secret input is passed through stdin into private tmpfs, not command arguments, environment, image layers or Docker logs. Stored secrets are not read back to the UI. Rust-owned secret buffers are zeroized; copies in JS, OpenVPN, Python, drivers, swap or OS backups cannot be guaranteed erased.

The loopback relay accepts one fixed destination and uses a random token for the container connection. Same-user host processes and Docker itself are trusted. Session drop aborts relay/process tasks and removes only its UUID-named container. Stdin EOF and a 30-second heartbeat deadline bound orphan lifetime after app/CLI failure. Route probes are serialized and bounded; status polling reads local memory without SQL. Replacement creates and validates the new route/session before swapping; VPN servers with single-session client credentials can nevertheless invalidate the prior tunnel themselves.

See CONNECTIONS.md for supported profile/authentication formats and VALIDATION.md for evidence. User-provided external VPNs, OS packet-capture egress auditing and independent security review remain outside the local fixture tests.

## Implemented controls

| Area                  | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Transport             | Verified certificate/hostname TLS by default. Unencrypted mode accepts literal loopback IPs only. No automatic downgrade or URL credentials. PostgreSQL offers an explicit `require` option that encrypts without verifying certificate/hostname; it is vulnerable to server impersonation and is never selected automatically. Verified PostgreSQL TLS accepts bounded CA PEM bundles (optionally saved with local bookmarks). MySQL/Redis reject these PostgreSQL-only settings. Redis sets TLS 1.2 minimum. MySQL uses the native TLS driver's defaults with certificate and hostname verification enabled.                                                                                                                                                                                          |
| Secrets               | Credential-bearing request/runtime profile types do not implement Debug or Serialize. SavedConnection is a separate password-free type. Password ownership uses Zeroizing, frontend fields clear after submission and engine changes. No query/result persistence, analytics, external AI or remote fonts. Password-free bookmarks/tab identities persist locally; optional passwords use Mac login Keychain or Windows Credential Manager with explicit Local persistence. Signed release updater contacts GitHub without database context. Driver/JS/OS copies are not guaranteed to be erased.                                                                                                                                                                                         |
| MySQL identity        | Only MySQL 8.x, dedicated direct SELECT/SHOW VIEW/USAGE grants. SHOW GRANTS is rechecked on each operation; role grants, FILE, EXECUTE, writes, PROXY and GRANT OPTION are rejected. No grants are changed by the app.                                                                                                                                                                                                                                                                      |
| MySQL queries         | InnoDB base tables with supported scalar columns only; views, generated columns, binary/JSON/spatial types excluded. MySQL AST validation accepts a small single-SELECT subset and reconstructs SQL. No functions, multi-statements, INTO OUTFILE, locks, administration or arbitrary SQL writes. Fixed session sql_mode; backslashes, double-quoted identifiers and block/executable comments in user SQL are rejected. Use backticks and bound UI filters.                                |
| MySQL isolation       | Dedicated connection per operation; START TRANSACTION READ ONLY, 10-second server execution timeout, 2-second metadata lock wait. Disconnect wrapper avoids driver's default background result-draining behavior. Manual saves are rejected for this engine.                                                                                                                                                                                                                                |
| MySQL resource bounds | 200 displayed rows/page, 1,000 SQL rows, 4 MiB retained result bytes, 4 MiB driver packet limit, 20 filters/4,096 bytes each, catalog capped at 16,384 column records and 500 tables. Application operation deadline is 15 seconds.                                                                                                                                                                                                                                                         |
| Redis commands        | Separate typed IPC takes an array of arguments, never a shell string. Fixed command/arity/range allowlist. No SET, DEL, GETDEL, FLUSH, EVAL/EVAL_RO, FCALL, MODULE, CONFIG, ACL, transactions, pub/sub, blocking reads or user AUTH/SELECT. Cluster redirects are not followed.                                                                                                                                                                                                             |
| Redis resources       | SCAN/HSCAN/SSCAN/ZSCAN always use COUNT 100; COUNT is a hint. GET becomes EXISTS + GETRANGE limited to 64 KiB. List/sorted-set ranges are capped at 200 entries. A stream wrapper caps received wire bytes at 8 MiB per short-lived operation before driver decoding; output conversion has a 4 MiB accounting budget and arrays at most 10,000 elements. Operations have a 15-second deadline, connection/auth 6 seconds, responses 10 seconds. Cancellation drops the driver task/socket. |
| Frontend              | Text-only rendering for database values/errors. CSP disallows remote scripts, frames and ordinary frontend network destinations. Explicit main-window Tauri command capabilities, no filesystem/shell plugin permissions.                                                                                                                                                                                                                                                                   |
| Errors                | Do not return raw MySQL/Redis errors or connection URIs, which could disclose values or credentials.                                                                                                                                                                                                                                                                                                                                                                                        |

Redis ACLs remain server-authoritative. The application allowlist protects its own command paths even with an admin account, but it does not audit or reduce that account's other capabilities. Provision a dedicated restricted ACL user. The disposable fixture demonstrates individual command grants; do not copy test credentials into a real deployment. GET preview also requires EXISTS and GETRANGE, and inspecting a key requires TYPE/TTL. INFO is optional and may be denied without preventing connection.

MySQL overview uses server-wide Threads_connected/Threads_running and Com_commit/Com_rollback counters. The COMMIT/ROLLBACK figures count explicit statements, not all transactions or autocommit work. Index scan counts are not fabricated when unavailable.

The UI does not provide manual MySQL/Redis editing in this release. Existing explicit PostgreSQL manual saves retain their separate typed transaction path; future AI must never receive that path or its session identity.

## Dependency scan

- `pnpm audit --json`: no reported vulnerabilities at review time.
- `cargo audit`: found a `time` stack-exhaustion advisory, RUSTSEC-2026-0009. Updated the lockfile from 0.3.45 to 0.3.55, which is outside the affected range.
- Two **remaining** advisories affect `quick-xml` 0.38.4 through `plist` 1.8.0/Tauri: RUSTSEC-2026-0194 (quadratic attribute checking) and RUSTSEC-2026-0195 (unbounded namespace declarations). The current upstream dependency requirement does not accept the patched 0.41 line; a normal `cargo update -p plist` did not resolve these. They are not suppressed in audit configuration.
- Source inspection of the installed `plist` XML reader found plain `Reader`, not `NsReader`, and no attribute iteration. Application code does not parse database data as XML. This reduces the identified exposure of these particular paths, but is not proof of universal unreachability across every target/dependency. Track the upstream update before treating the release as security-cleared.
- Full-lockfile informational warnings also include Linux GTK `glib` 0.18.5 unsoundness (RUSTSEC-2024-0429) and unmaintained `proc-macro-error` (RUSTSEC-2024-0370). `cargo tree` for the macOS build does not include these packages. Linux is not a supported release target here; Windows still needs native build/run validation.

## Test evidence and remaining limits

Tests exercise real isolated MySQL 8.4 and Redis 8 servers: connection, metadata, precision, filtering/sorting, read commands, denied mutation/indirect commands, rejected write accounts, cross-engine API rejection, password-safe errors, disconnect and TLS rejection without fallback. Chromium/WebKit cover engine defaults and Redis UI behavior using a clearly marked IPC stub; native packaging smoke tests provide the separate actual IPC evidence in VALIDATION.md.

The OS, installed binary, certificate trust store and database administrator remain trusted. This is not a sandbox for a malicious server speaking malformed wire protocols. Byte caps reduce normal large-response exposure but are not a bound on total process heap or all decoder allocations. Reads still consume server resources and alter internal counters/caches. SCAN is not a snapshot and can repeat/omit keys during concurrent changes; collection scan count is not exact. GET preview/TTL/type are separate reads. Binary responses are displayed as hex; the key browser lists UTF-8 keys only. Redis Cluster/Sentinel and streams are not implemented.

No complete native packet-capture/OS egress audit, fuzzing, independent pentest, Windows native smoke test or signed distribution validation was performed. The app does not intentionally transmit database data to other services, but that is not an OS-wide firewall guarantee.

## Signed distribution and updates (2026-10-14)

- Development/default builds have no updater public key and never fetch update metadata. Signed release configuration embeds only the verification key, never a GitHub token or private signing key.
- Updates use HTTPS metadata from `sparkclan123/buggy-table-releases`; artifact URLs must originate in that repository. GitHub redirects downloads to its asset CDN. These requests disclose normal transport metadata (IP/user agent), but no DB credentials, SQL, result rows or connection names. Automatic checks can be disabled; manual checks are explicit.
- Tauri verifies the mandatory updater signature before installation. OS signatures are separate: Apple Developer ID + notarization, Azure Artifact Signing for Windows. Release workflow verifies them and only creates a draft after all three platform builds succeed.
- Native update installation shares the database job lock. Active queries, metadata, saves and connection preflight block installation; new DB jobs cannot begin while an update holds the lock. The UI also blocks installation for pending/uncertain edits across all tabs and locks the workspace while downloading/installing.
- Downloads are capped at 256 MiB and 180 seconds; checks time out after 15 seconds. Errors return sanitized messages and restore the workspace. Release notes render as plain text.
- No updater permissions are exposed directly to JS; only `check_update` and `install_update` wrappers are permitted in the main window.
- Residual limits: updater signature authenticates the package and its bound version (`requireSignedVersion`); displayed release notes remain unsigned plain text. GitHub account and release secrets require protection. Native install/restart across real OS versions and real signing services must be tested with two signed releases before promoting the first public release. Processes terminated outside the window guard cannot preserve unsaved work. This is a full-package updater, not delta patching.


## Connection bookmarks / schema isolation — 0.1.3

- Metadata is a versioned JSON allowlist (500 entries / 4 MiB / 40 tabs per entry), written through an atomic tempfile replacement. Unix directory/file permissions are 0700/0600; Windows uses the user's local app data directory and inherited ACLs. Corrupt/newer formats are rejected without overwriting the original.
- Passwords never enter that serialized type. The opt-in vault is separate and keyed by an opaque UUID. Windows persistence is explicitly Local rather than Enterprise; Mac uses the login Keychain store. Vault errors are sanitized; no stored secret is returned through IPC. Failed vault writes leave a usable bookmark requiring manual password entry.
- Startup loads bookmarks without database activity. Connections are re-established only on an explicit Reconnect. Removing a bookmark removes its credential first; disconnecting only releases the session.
- PostgreSQL catalog lookup is bound and requires schema USAGE. Browse/SQL/index/save carry the owning schema and enforce the same table/role policies. Same-named tables in different schemas cannot share a workspace identity.
- UI protects unsaved work across every connection when closing/updating; clean result caches are bounded. These controls do not encrypt endpoint metadata, protect against another process running as the same user, or control OS backups/swap.
